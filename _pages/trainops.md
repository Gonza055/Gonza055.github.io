  <section class="case3-section">
    <div class="case3-section__head">
      <p class="case3-label">The Problem</p>
      <h2>Large simulation outputs were slowing down the analysis loop.</h2>
      <p>TrainOps scenarios produced large, fragmented output sets that required repeated processing before analysts could compare delays, network behavior, service assumptions, and operational bottlenecks.</p>
    </div>

    <div class="case3-problem">
      <div class="case3-copybox">
        <p>The recurring task was not only to run simulations. It was to make the outputs <strong>consistent, analysis-ready, and comparable</strong> so more time could be spent interpreting the scenario rather than rebuilding the same preparation workflow.</p>
      </div>
      <div class="case3-insight" style="border-color:#fed7cc;">
        <strong>Core engineering question</strong>
        <p>How can raw simulation output become a repeatable analytical pipeline that supports faster scenario evaluation?</p>
      </div>
    </div>
  </section>

  <section class="case3-section">
    <div class="case3-section__head">
      <p class="case3-label">Evidence at a Glance</p>
      <h2>Automation changed where the analysis time went.</h2>
    </div>

    <div class="case3-results">
      <article class="case3-result"><strong>200k+</strong><p>TrainOps simulation records processed and analyzed.</p></article>
      <article class="case3-result"><strong>~70%</strong><p>reduction in simulation-output processing time.</p></article>
      <article class="case3-result"><strong>Python + C++</strong><p>automation utilities used to parse, structure, and transform outputs.</p></article>
      <article class="case3-result"><strong>Multiple scenarios</strong><p>compared for delays, network performance, and operational bottlenecks.</p></article>
    </div>
  </section>

  <section class="case3-section">
    <div class="case3-section__head">
      <p class="case3-label">Data Pipeline</p>
      <h2>Raw outputs → structured datasets → scenario comparison.</h2>
      <p>The work focused on standardizing the repetitive parts of simulation analysis so that the same preparation logic could be reused across cases.</p>
    </div>

    <div class="case3-process">
      <div class="case3-step"><strong>01 · Parse</strong><span>Read large TrainOps output files and extract the fields needed for analysis.</span></div>
      <div class="case3-step"><strong>02 · Structure</strong><span>Normalize fragmented outputs into consistent, analysis-ready datasets.</span></div>
      <div class="case3-step"><strong>03 · Enrich</strong><span>Combine simulation results with rider-survey responses and onboard sensor data where relevant.</span></div>
      <div class="case3-step"><strong>04 · Compare</strong><span>Evaluate delays, network performance, service configurations, and operational bottlenecks across scenarios.</span></div>
    </div>
  </section>
